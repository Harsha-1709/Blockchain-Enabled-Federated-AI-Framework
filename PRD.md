# Product Requirements Document (PRD)

## Project: Blockchain-Enabled Federated AI Framework for Secure Distributed Intelligence
**Document Version:** 1.0.0  
**Target Solution:** Clone & Clean-Room Reproduction Specification  
**Benchmark Target:** Canadian Institute for Cybersecurity Intrusion Detection Benchmark (CICIDS2017)  
**Classification Domain:** Distributed Multi-Class Network Intrusion Detection System (NIDS)  

---

### 1. Executive Summary & Problem Formulation

#### 1.1 Vision & Core Value Proposition
The **Blockchain-Enabled Federated AI Framework** is an enterprise-grade, decentralized cybersecurity threat intelligence platform. It enables competitive, regulated, or isolated multi-institutional silos—specifically **Healthcare Consortia (Hospital A)**, **Financial Institutions (Bank B)**, and **Critical Edge Infrastructure (IoT Node C)**—to collaboratively train a Deep Neural Network (DNN) Intrusion Detection System without ever consolidating or exfiltrating raw network telemetry.

By orchestrating Federated Learning (FL) via a **Permissioned Blockchain Ledger** and **Solidity Smart Contracts**, the framework overcomes the single-point-of-failure (SPoF) and vulnerability vectors of centralized parameter servers. It integrates **$(\epsilon, \delta)$-Differential Privacy (DP-SGD)**, **ECDSA asymmetric digital signatures**, and a **Cosine Distance Byzantine Shield** to deliver a zero-trust, poisoning-resilient, tamper-evident collaborative defense ecosystem.

#### 1.2 Systemic Gaps & Core Problems Solved
1. **Raw Telemetry Exfiltration & Regulatory Non-Compliance**: Centralized data aggregation violates GDPR (Art. 25 Privacy by Design), HIPAA (45 CFR §164 ePHI protection), and PCI-DSS (Requirement 3/10). *Solution*: Data stays strictly local within organizational silos.
2. **Central Parameter Server Bottleneck & Vulnerability**: Standard FedAvg relies on a central coordinator susceptible to DDoS, insider parameter alteration, or outage. *Solution*: Decentralized consensus and smart contract governance.
3. **Model Poisoning & Byzantine Insecurity**: Adversarial nodes can inject sign-flipped gradients, high-variance Gaussian noise, or targeted backdoor triggers to corrupt multi-class intrusion detection. *Solution*: Multi-tier Byzantine filtering (Cosine Distance Shield and Multi-Krum) that identifies and slashes malicious updates before aggregation.
4. **Absence of Verifiable Forensics**: Standard FL does not provide an immutable, cryptographic record of who contributed what, when updates occurred, and whether the aggregated model was tampered with. *Solution*: SHA-256 block chaining, binary Merkle roots, Proof-of-Authority (PoA) validator signatures, and one-click JSON compliance export.
5. **Smart Contract Gas Bottleneck (The BAFFLE Limitation)**: Prior literature (e.g., Ramanan et al. BAFFLE) attempted to calculate high-dimensional neural weight aggregations directly inside the Ethereum Virtual Machine (EVM), resulting in prohibitive gas costs. *Solution*: A **Hybrid On-Chain / Off-Chain Architecture** where heavy mathematical computation occurs off-chain in trusted client nodes, while cryptographic weight hashes ($H(w)$), Merkle roots, participant registries, and Byzantine slashing events are committed on-chain.

### 3. Functional Requirements (FR)

#### FR-1: CICIDS2017 Dataset Ingestion & Non-IID Silo Partitioning
- **FR-1.1**: The framework must support the 78 continuous numerical flow features generated by CICFlowMeter and classify across 15 distinct classes (1 `BENIGN` + 14 attack types: `Bot`, `DDoS`, `DoS GoldenEye`, `DoS Hulk`, `DoS Slowhttptest`, `DoS slowloris`, `FTP-Patator`, `Heartbleed`, `Infiltration`, `PortScan`, `SSH-Patator`, `Web Attack - Brute Force`, `Web Attack - Sql Injection`, `Web Attack - XSS`).
- **FR-1.2**: Provide a high-fidelity synthetic benchmark generator producing distinct statistical moments (mean, variance, skew) reflecting real-world Non-IID attack allocations:
  - **Hospital A (Healthcare Silo)**: High concentration of `Infiltration` (20%), `Heartbleed` (15%), `PortScan` (15%), and `BENIGN` (50%).
  - **Bank B (Financial Silo)**: High concentration of `DDoS` (20%), `DoS GoldenEye` (15%), `FTP-Patator` (10%), `SSH-Patator` (10%), and `BENIGN` (45%).
  - **IoT Node C (Edge Gateway Silo)**: High concentration of `Bot` (ARES Botnet) (25%), `DoS slowloris` (15%), `Web Attack - Brute Force` (8%), `Web Attack - Sql Injection` (6%), `Web Attack - XSS` (6%), and `BENIGN` (40%).
- **FR-1.3**: Provide a balanced global test dataset across all 15 classes for unbiased global evaluation.
- **FR-1.4**: Apply global feature standardization (`StandardScaler` logic) based on baseline benign distributions to normalize input features without cross-silo data contamination.

#### FR-2: Deep Neural Network (DNN) IDS Classifier
- **FR-2.1**: Implement a PyTorch multi-layer feedforward architecture:
  $$\text{Input}(78) \to \text{Linear}(128) \to \text{BatchNorm1d} \to \text{LeakyReLU}(0.1) \to \text{Dropout}(0.25)$$
  $$\to \text{Linear}(128, 64) \to \text{BatchNorm1d} \to \text{LeakyReLU}(0.1) \to \text{Dropout}(0.20)$$
  $$\to \text{Linear}(64, 32) \to \text{BatchNorm1d} \to \text{LeakyReLU}(0.1)$$
  $$\to \text{Linear}(32, 15)$$
- **FR-2.2**: Support parameter vector flattening (`get_flat_parameters()`) into a contiguous 1D NumPy float32 array, and weight restoration (`set_flat_parameters()`).
- **FR-2.3**: Deliver comprehensive multi-class evaluation metrics: Loss, Accuracy, Weighted Precision, Weighted Recall, Weighted F1-Score, Per-Class Detection Rate, and a $15 \times 15$ Confusion Matrix.

#### FR-3: Differential Privacy Engine (DP-SGD)
- **FR-3.1**: Implement local gradient manipulation in PyTorch during backpropagation:
  1. $L_2$ gradient norm clipping to maximum threshold $C$ (default $C = 1.0$).
  2. Injection of calibrated Gaussian noise $\mathcal{N}(0, \sigma^2 C^2 \mathbf{I})$ scaled by batch size $\sqrt{B}$ (default $\sigma = 0.3 - 0.5$).
- **FR-3.2**: Implement an advanced composition privacy accountant tracking cumulative $(\epsilon, \delta)$ expenditure across communication rounds.
- **FR-3.3**: Support dynamic toggling of Differential Privacy (enable/disable) for benchmarking privacy-utility trade-offs.

#### FR-4: Cryptographic Verification Engine
- **FR-4.1**: Each participant must maintain a dedicated SECP256R1 (NIST P-256) ECDSA asymmetric key-pair.
- **FR-4.2**: Produce deterministic SHA-256 fingerprints of model parameter vectors serialized at 32-bit floating point precision.
- **FR-4.3**: Sign the SHA-256 weight hash using the node's ECDSA private key and verify incoming signatures against registered public keys in PEM format.
- **FR-4.4**: Implement a cryptographic Binary Merkle Tree generator that hashes paired leaf transaction hashes to compute an unforgeable Merkle Root for every round block.

#### FR-5: Byzantine Fault Tolerance & Model Poisoning Defense
- **FR-5.1**: Provide a pluggable Byzantine defense engine supporting:
  1. **Cosine Distance Shield** (Consensus Alignment): Computes the coordinate-wise median direction and measures cosine similarity $\mathcal{S}_k$. Rejects updates with $\mathcal{S}_k < \tau$ (default $\tau = 0.20$).
  2. **Multi-Krum**: Evaluates pairwise Euclidean distances and selects the $m - f$ candidates minimizing Euclidean distance sums.
  3. **Coordinate-wise Median / Trimmed Mean**: Aggregates median values along each parameter coordinate.
- **FR-5.2**: Provide an Adversarial Attack Simulator capable of generating:
  - **Sign Flipping Attack**: Multiplies weights by negative scalar (e.g., $-4.0 \times$).
  - **Gaussian Noise Attack**: Injects high-variance Gaussian noise.
  - **Targeted Backdoor Attack**: Perturbs specific input/output weight layers to blind the IDS to specific attacks.
- **FR-5.3**: Automatically slash identified Byzantine adversaries, log their status on-chain, and exclude them from Federated Averaging (FedAvg).

#### FR-6: Permissioned Blockchain Ledger Engine
- **FR-6.1**: Maintain an in-memory or persisted cryptographic blockchain where each block contains:
  - Block index, Round number, Timestamp, Previous block hash ($H_{\text{prev}}$).
  - Merkle Root of round transactions.
  - Global Model SHA-256 weight hash.
  - Round metrics (Accuracy, Loss, F1, accepted/rejected counts, DP status).
  - Proof-of-Authority (PoA) validator ID and ECDSA signature.
- **FR-6.2**: Genesis Block initialization with zero-pointer `0000...0000` and confirmed consortium genesis status.
- **FR-6.3**: Implement a rigorous integrity auditor (`verify_ledger_integrity()`) that re-computes every block hash, verifies previous-hash chaining, re-derives Merkle roots, and verifies validator signatures.
- **FR-6.4**: Provide a tamper simulation function that mutates historical block contents to demonstrate immediate detection and chain-invalidation.

#### FR-7: Smart Contract Governance Layer (`FederatedAuditLedger.sol`)
- **FR-7.1**: Solidity v0.8.20 contract deployable to EVM-compatible permissioned networks (e.g., Hyperledger Besu, Polygon Edge, Arbitrum Orbit, local Anvil/Hardhat).
- **FR-7.2**: Role-based access control (Admin governance, active participant modifiers).
- **FR-7.3**: Participant lifecycle: Registration, activation, suspension, and slashing.
- **FR-7.4**: Round lifecycle: Start round, submit weight commitment hash and signature, slash malicious participant, and finalize round with updated global model hash and Merkle root.
- **FR-7.5**: Emits standard EVM events: `ParticipantRegistered`, `RoundStarted`, `CommitmentSubmitted`, `ByzantineClientSlashed`, `RoundFinalized`.

#### FR-8: FastAPI High-Performance Backend
- **FR-8.1**: Expose asynchronous and synchronous REST endpoints:
  - `GET /api/status`: Current system architecture state, clients, baseline metrics.
  - `POST /api/train-round`: Executes a federated round with configurable hyperparameters (epochs, learning rate, DP toggle, attack toggle, attack type, Byzantine method).
  - `GET /api/blockchain`: Returns the complete ledger history and validation report.
  - `POST /api/blockchain/verify`: Audits ledger cryptographic integrity.
  - `POST /api/blockchain/tamper-test`: Injects a simulated hash mutation.
  - `POST /api/reset`: Reinitializes orchestrator and rebuilds genesis chain.
  - `GET /api/confusion-matrix`: Returns the $15 \times 15$ test confusion matrix.
  - `GET /api/export-audit`: Downloads a forensic audit report in JSON format.
- **FR-8.2**: Mount and serve static frontend assets without external dependency requirements.

#### FR-9: Interactive SOC Glassmorphism Web Cockpit
- **FR-9.1**: Dark-mode aesthetic styled with modern CSS variables, glassmorphism backdrop filters, and ambient glow effects.
- **FR-9.2**: Three-tier architecture breadcrumb banner displaying real-time node statuses (Hospital A, Bank B, IoT Node C).
- **FR-9.3**: Interactive execution controls: Single round, batch 3 rounds, attack injection toggle, attack type selector, Byzantine defense selector, DP toggle.
- **FR-9.4**: Real-time convergence visualizations via Chart.js: Dual-axis Accuracy & Loss curves, and multi-class Radar / Bar charts.
- **FR-9.5**: Live horizontal Blockchain Block Explorer displaying block cards, transaction counts, Merkle roots, and full inspection modal.
- **FR-9.6**: Interactive tamper detection demonstration with red-alert UI feedback.
- **FR-9.7**: One-click download of the official GDPR/HIPAA forensic audit report.

### 4. Non-Functional Requirements (NFR)

#### 4.1 Performance & Latency
- **NFR-1.1 Training Round Execution**: A single 3-client federated round with DP-SGD and 1 epoch per node must complete within **< 3.5 seconds** on modern commodity multi-core CPUs.
- **NFR-1.2 Test Suite Execution**: The complete automated unit test suite (`tests/test_system.py`) covering all 7 modules must pass in **< 4.0 seconds**.
- **NFR-1.3 API Latency**: Telemetry and query endpoints (`/api/status`, `/api/blockchain`) must respond in **< 50 milliseconds**.

#### 4.2 Security, Privacy & Integrity
- **NFR-2.1 Zero Raw Data Exfiltration**: Under no circumstance should raw feature tensors or network packet metadata leave the local client boundary.
- **NFR-2.2 Differential Privacy Guarantee**: Maintain an upper bound privacy budget of $\epsilon < 10.0$ and $\delta \le 10^{-5}$ over 10 consecutive training rounds.
- **NFR-2.3 Non-Repudiation**: Every model update must be signed by an authorized SECP256R1 key; forged or altered signatures must be rejected at Tier 2.
- **NFR-2.4 Cryptographic Tamper Evidence**: Any alteration to historical blocks (timestamps, previous hashes, Merkle roots, metrics) must be detected with 100% certainty by `verify_ledger_integrity()`.

#### 4.3 Scalability & Resource Efficiency
- **NFR-3.1 Gas Cost Optimization**: Weight vectors must **never** be posted directly to EVM storage. Only 32-byte SHA-256 hashes and Merkle roots are committed on-chain, keeping EVM transaction costs constant $O(1)$ with respect to neural network size.
- **NFR-3.2 Memory Footprint**: Python orchestrator process must maintain a baseline memory footprint of **< 500 MB RAM** during training and evaluation.

#### 4.4 Reliability & Portability
- **NFR-4.1 Zero Native Compilation Dependencies**: The Python backend must run on standard Python 3.11+ environments using pure-Python/NumPy/PyTorch wheels without requiring C++ compilation toolchains.
- **NFR-4.2 Cross-Platform Compatibility**: Fully compatible with Linux (Ubuntu 22.04+), macOS (ARM64/x86_64), and Windows 11 (PowerShell/CMD).
